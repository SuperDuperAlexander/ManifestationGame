## 2. What the game is

A calm, spiritual browser game. No enemies. The player walks through small open regions with a fairy companion, finds fog clouds that carry inner blockades ("I'm not worthy"), and dissolves them by **breathing** — never by force. Dissolved blockades become planks of a light bridge that leads to the next chapter.

Inspiration: a small, compact "Zelda: Breath of the Wild" feeling of free exploration, plus a pilgrimage structure like "Journey to the West" (stations, trials, a guide).

## 3. Decisions (and why) — do not reopen without asking Alexander

| # | Decision | Why |
|---|---|---|
| 1 | **Babylon.js**, browser game, mobile first | Alexander's choice. Runs everywhere, no install. |
| 2 | Art style = **Design 3 "paper diorama"** (`docs/style-reference.png`) | Layered paper look maps directly onto 2.5D layers. Soft gradients look premium but cost no performance. |
| 3 | **Diorama hybrid** instead of pure 2.5D parallax | Pure image layers only work on a camera rail. Alexander wants free walking. So: simple real 3D ground + paper-card props + painted parallax backdrops. |
| 4 | **Fixed camera angle**, follows player, not rotatable | Paper cards only look right from the front. Also keeps rendering predictable and cheap. |
| 5 | **Open region per chapter** (5–8 zones), seamless streaming inside, soft fog-gate transition between chapters | Feels free, stays plannable, easy to extend chapter by chapter. Rejected: one fully open world (too hard to plan, test and extend). |
| 6 | **Fog = blockade = loading cover** | Fog walls hide zone streaming. Story and tech fit together. |
| 7 | **Breathing is the core mechanic**: Space = inhale, Shift = exhale; mobile: hold button = inhale, release = exhale | Alexander's idea. The lesson lives in the mechanic: force fails, breathing releases. |
| 8 | Push/strike on fog **fails on purpose** (fog wobbles, grows denser); fairy says "Force doesn't help here. Breathe." | Alexander's idea. Teaches acceptance through play. |
| 9 | **Fairy companion**: intro on the meadow, orbits the player, flies to points of interest, short lines | Alexander's idea. She is the guide of the journey. |
| 10 | **Player = procedural red-cloak figure** built in code (option A) | Fast, fits the minimal paper style, no cost. Clean interface so a GLB model can replace it later (option B). |
| 11 | Fairy, fog, glow, light ring, light bridge, UI = **all in code** | No image files needed for these. |
| 12 | **All in-game text in English** | Alexander's decision. |
| 13 | **WebP** for the game, PNG stays as original; automatic conversion script | ~70–80 % smaller downloads. Rejected for now: KTX2 (more setup, alpha edge issues). Revisit only if phone GPU memory is a problem. |
| 14 | Assets live in **`public/assets/ch1/`** with subfolders `bg/`, `textures/`, `props/` | Alexander's folder choice. PNGs are removed from the production build. |
| 15 | **No automatic mirroring of props** | All art is lit from the right. Mirroring would flip the light. Only grass and flowers may mirror. |
| 16 | 5 backdrop layers incl. **`mountains_farthest`** | Two mountain variants were different enough to give extra depth. |
| 17 | **Haze on `landmark_far`** (start value 0.35) | The bridge art is too sharp and warm for its distance. Fixed in shader, no new image. |

## 4. Asset status — chapter 1 complete (22 images)

All images were generated by Alexander in ChatGPT with `docs/style-reference.png` as style reference, then checked by Claude:

- Sizes correct (backgrounds 1536×1024, textures and props 1024×1024, gate 1024×1536).
- Transparency correct on all layers and props. No object touches the image edge.
- Ground textures tested 2×2: no visible seams.
- Light direction: from the right, on every image.

Notes per asset:
- `sky.png`: the calm version with few clouds (the busy version was rejected).
- `mountains_farthest.png`: bottom rows are slightly transparent — fine, `mountains_far` covers them.
- `landmark_far.png`: bottom floats in the air — place it so `mountains_near` covers it. Needs haze.
- Two sub-styles exist: plants are flat paper; stones, well, ruins, gate look like soft 3D renders. This matches the style reference. Accepted.
- `well.png` is the most detailed prop. Accepted.
- `ground_stone.png` reads more like a wall than paving. Good for the ruins zone.
- `tree_cypress.png` has a lot of empty margin — the trim step in the conversion script handles it.

Rejected duplicates (should not be in the repo): `sky_2`, `mountains_far_2`, `landmark_far_2`, `tree_round_2`. If you find them, list them and ask before deleting.
